# 착수서
| 항목 | 작성 내용 |
|---|---|
| 프로젝트명 | GCP 웹 서비스 관리 접속 경로 보안 검토 |
| 목적 | 고객 HTTP 접근을 유지하면서 VM 관리 접속 경로와 불필요한 네트워크 허용을 제한하고, 변경 결과를 검증한다. |
| 대상 | 지정된 acme-vpc, 관리/애플리케이션 서브넷, bastion·juice-shop VM, 관련 방화벽 규칙과 네트워크 태그 |
| 환경 | Google Skills가 제공한 임시 교육 프로젝트(Lab). 운영 서비스나 실제 고객 시스템이 아님. |
| 역할 | 수행자·검토자: 본인. 독립적인 검토/승인자는 없음. 승인 절차는 개인 프로젝트의 모의 기록이다. |
| 허용 작업 | 해당 랩에서 요구하는 방화벽/태그/VM 작업 및 허용된 범위의 설정 조회·접속 확인 |
| 제외 | Juice Shop 취약점 공격, 비밀번호 추측, 전체 포트 스캔, IAM 정책 임의 확대, 새로운 서버·유료 분석 서비스 추가 |
| 가상 업무 가정 | 고객은 공개 웹페이지를 조회하고, 관리자는 SSH로 서버를 관리한다. 데이터 민감도·매출·실제 피해액은 미확인이다. |
| 변경 영향 | 규칙 삭제와 태그 변경 중 HTTP 또는 SSH가 일시 중단될 수 있다. |
| 완료 기준 | 필수 요구의 설정/시험 결과를 연결하고, 미충족·미검증·범위 외 항목을 별도로 설명한다. |

## 1. 요구사항과 검수 기준
| ID | 요구사항 | 적합 기준 | 확인 방법 |
|---|---|---|---|
| R01 | 고객 HTTP 제공 | juice-shop TCP/80에 공개 IPv4 소스 허용, 실제 페이지 정상 조회 | 규칙·태그 검토 + T01 |
| R02 | bastion 외부 IP 없음 | 검토 NIC에 외부 IPv4 accessConfig가 없고 외부 IPv6 여부도 확인 | VM 설정 + T04 |
| R03 | bastion SSH는 IAP 경유 | IAP IPv4 범위의 TCP/22가 bastion에 허용되고 그 밖의 우회 허용이 없음; 실제 IAP SSH 성공 | 유효 규칙 검토 + T02 |
| R04-S | 엄격한 업무 목표: 웹 서버 SSH는 bastion 한 대에서만 | 다른 호스트가 동일 허용에 포함되지 않는 소스 제한 + bastion에서 로그인 성공 | 소스 식별 검토 + T03 |
| R04-L | 랩에서 요구하는 구현 조건 | 실제 관리 서브넷 CIDR → juice-shop TCP/22 허용 | 규칙·태그 검토 + T03 |
| R05 | 웹 서버에 인터넷 직접 SSH 미허용 | 인터넷 일반 소스 TCP/22를 허용하는 유효 규칙이 없으며 새 직접 연결이 성립하지 않음 | 규칙 검토 + T05 |
| R06 | 공개 서비스 범위 제한 | 관련 유효 ingress 규칙상 HTTP 외 불필요한 공개 허용 없음 | 모든 관련 규칙 검토; 포트 하나의 시험만으로 전체 증명 불가 |
| R07 | 변경 추적 가능 | 전후 설정, 작업 시간·행위, 시험 조건·결과가 증적 ID로 연결됨 | 증적 대장·CHG-01·시험표 |
