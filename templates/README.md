# 실습 기록 양식

새 실습을 시작할 때 필요한 양식을 복사해 사용한다. 원본 양식은 이 폴더에 두고, 실제 기록은 `labs/실습명/` 아래에서 작성한다.

| 양식 | 복사할 위치 | 용도 |
|---|---|---|
| [lab-readme.md](lab-readme.md) | `labs/실습명/README.md` | 실습 개요와 결과 요약 |
| [finding.md](finding.md) | `labs/실습명/reports/03-findings.md` | 확인한 문제와 조치 추적 |
| [validation.md](validation.md) | `labs/실습명/reports/05-validation.md` | 시험 조건·관찰 결과·판정 |

## 작성 순서

1. 실습 시작 전에 README의 목적·범위와 재점검표의 기대 결과를 작성
2. 현재 상태를 조사하면서 Finding에 관찰 사실과 근거를 기록
3. 변경 후 시험을 실행하고 실제 결과·증적·판정을 작성
4. 재점검 결과에 따라 Finding 상태를 갱신하고 README에 주요 결과를 요약

확인하지 못한 항목은 사유와 함께 `미확인` 또는 `미실행`으로 기록한다. 해당하지 않는 선택 항목은 삭제해도 된다. 양식 안의 HTML 주석은 작성 안내이다.

## ID와 증적

실습별 접두어를 정해 사용한다. 네트워크 실습은 `NET`, IAM 실습은 `IAM`, 취약점 관리 실습은 `VULN`처럼 구분할 수 있다.

| 구분 | 네트워크 실습 예시 |
|---|---|
| 요구사항 | `NET-R01` |
| Finding | `NET-F01` |
| 변경 | `NET-CHG01` |
| 시험 | `NET-T01` |
| 증적 | `NET-E001` |

ID는 한번 부여하면 상태가 바뀌어도 유지한다. 같은 원인의 문제를 여러 문서에서 다룰 때는 기존 ID를 참조한다.

공개용 증적은 실습 폴더의 `evidence/`에 둔다. `reports/` 안의 문서에서 연결할 때는 `../evidence/파일명`을 사용한다. README에서는 `evidence/파일명`을 사용한다. 링크는 실제 파일을 추가한 뒤 연결한다.

## 기록 상태

Finding 상태와 시험 판정은 별도로 관리한다.

| Finding 상태 | 의미 |
|---|---|
| 확인 중 | 문제 여부와 영향을 조사하는 단계 |
| 미조치 | 문제를 확인했으나 아직 개선하지 않음 |
| 조치 중 | 변경 작업 진행 중 |
| 재점검 대기 | 변경은 수행했으나 결과를 검증하기 전 |
| 종료 | 정한 종료 조건을 증적으로 확인 |
| 해당 없음 | 조사 결과 문제에 해당하지 않음; 근거 기록 |

| 시험 판정 | 의미 |
|---|---|
| 미실행 | 아직 시험하지 않음 |
| 적합 | 관찰 결과가 기대 결과와 일치 |
| 부적합 | 관찰 결과가 기대 결과와 불일치 |
| 판단 보류 | 시험했으나 원인·조건·증적이 부족해 판단하지 못함 |
| 해당 없음 | 환경이나 검토 범위에 해당하지 않음; 사유 기록 |

시험 일부가 성공했다고 Finding을 자동으로 종료하지 않는다. 설정 확인과 동작 검증 등 미리 정한 종료 조건을 함께 확인한다. 남은 위험은 처리 방향과 함께 별도로 기록한다.
